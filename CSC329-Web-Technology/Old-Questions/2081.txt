1. eXtensible Markup Language
-markup language that defines set of ruels for encoding documetns in both human and machine
readable format
-designed to store and transport data in a structured, self-descriptive, and 
platform-independent format
-used for Vector Markup Language (VML) for graphics, SMIL 2.0 for reusable multimedia content,
and configuration languages

-starting tag: <?xml version="1.0" encoding="UTF-8"?> called xml declaration
-must have exactly one root element containing all other content
-all tags must be paired
-all tags must be propoerly nested, closed in reverse order htey were ordered
-tag nanmes are case sensistive, <book> and <Book> are different
-attribute values must appaer within quotes <element attribute="value">
-white space is presevred within elmenets unlike HTML tags
-tag name restrictions: no spaces,cant start with letters "xml",numer or punctuiaiont except _
-avoid html tags

<html>
<head>
    <title>Form Validation</title>
    <script>
        function validateForm()
        {
            var name = document.userForm.nameField.value;
            var country = document.userForm.countryField.value;
            var gender = document.userForm.genderField;
            var password = document.userForm.passwordField.value;
            var checkbox = document.userForm.checkboxField;

            // Name regex (only letters, min 3 chars)
            const namePattern = /^[A-Za-z]{3,}$/;

            // Password regex (min 6 chars, at least 1 number, 1 uppercase, 1 special
            const passwordPattern = /^(?=.*[A-Z])(?=.*\d)(?=.*[^A-Za-z\d]).{6,}$/;

            if(name == "")
            {
                alert("Name can't be empty");
                return false;
            }
            else if(!namePattern.test(name))
            {
                alert("Name must contain only letters and at least 3 characters");
                return false;
            }

            if(country == "")
            {
                alert("Country can't be empty");
                return false;
            }

            var genderSelected = false;
            for(var i = 0; i < gender.length; i++)
            {
                if(gender[i].checked)
                {
                    genderSelected = true;
                    break;
                }
            }
            if(!genderSelected)
            {
                alert("Please select a gender");
                return false;
            }

            if(password == "")
            {
                alert("Password can't be empty");
                return false;
            }
            else if(!passwordPattern.test(password))
            {
                alert("Password must be at least 6 characters and include uppercase, special characters and numbers");
                return false;
            }

            if(!checkbox.checked)
            {
                alert("You must agree to terms and conditions");
                return false;
            }

            alert("Validation successful");
            return true;
        }
    </script>
</head>

4. client server architecture
-computing model that divides tasks between two distinct software types: client software 
(running on the user's device for interaction/presentation) and server software (running on a
remote computer to manage resources and perform high-power tasks)
-web clients are sofwatre used by suer to locate,request and display web pages
-eg: web browsers like chrome,firefox,safari
-web servers are sfowatre that hosts and delivers web pagse to clients based on HTTP requests
to multiple clinets simultaneously
-manages resrouces and performs high processing tasks
-eg: Apache or IIS Internet Information Service

1-Tier:
-interface and logic reside on the same system
-database is directly accesible to user
-used for development of local app where progammersd can direclty comomuncaite with database forr
quick response

2-Tier:
-application at client side communicates directly with a database at server side
-client side contains UI and application progarms
-server side proves functions like query processing and transsction amangemen
-clinet commumcaiton with dbms using applcaition to eastalbish conncetion with server side

3-Tier:
-client interacts with Server thourhg intermiedate layer, which communicates with the database
-applcaition cleint interacts with applcaition server
-end use has info about existsence of database beyond app server
-database has no idea about user beyond app server
