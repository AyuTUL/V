# Product

## Register

product

## Users
Primary users are student players and reviewers interacting with the project during demos, submissions, and quick evaluation sessions. Secondary users are instructors or administrators who need to review scores, manage quiz content, and adjust game difficulty without digging through the database directly.

## Product Purpose
Penalty Shootout is a simple student project that demonstrates a complete PHP and MySQL web application loop through a playable football penalty game. The product combines authentication, turn-based gameplay, score persistence, leaderboard ranking, quiz-based recovery mechanics, and a small admin panel for managing content and system settings. Success means the project feels coherent, works reliably in a demo setting, and clearly shows the range of features the student implemented.

## Brand Personality
Sporty, clear, no-nonsense. The interface should feel fast to read, easy to operate, and grounded in arcade football energy without drifting into theatrical esports styling or ornamental UI effects.

## Anti-references
Avoid glossy esports aesthetics, neon-heavy gaming UI, and fake enterprise dashboard polish. Avoid design choices that make the project feel like a marketing mockup rather than a working student-built game and admin tool. Avoid overcomplicated visual effects that compete with the gameplay loop or obscure the project structure during review.

## Design Principles
1. Make the gameplay loop obvious immediately, so a first-time reviewer can understand what to do without explanation.
2. Keep administration efficient and literal, so question management, score review, and difficulty updates feel dependable rather than decorative.
3. Use visual energy where it supports the football theme, but keep core interactions disciplined and readable.
4. Favor demo reliability over visual ambition, especially where animation, layout, or game feedback could create confusion.
5. Let the project show breadth clearly: game, scoring, quiz logic, and admin workflows should all read as parts of one system.

## Accessibility & Inclusion
Target basic WCAG AA contrast for core text and controls. Preserve readable labels, straightforward error feedback, and practical keyboard access where feasible within the project scope. Use motion with restraint and avoid effects that would make the game or admin screens harder to parse for users with reduced motion sensitivity.
